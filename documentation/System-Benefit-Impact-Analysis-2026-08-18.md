Fixes span `templates/index.html`, `qwen_service.py`, `document_routes.py`, `settings_routes.py`, the PDF/OCR service cluster, `document_model.py`, `retention_service.py`, and deployment/infra config.

## 1. System Stability & Error Rates

The largest cluster of fixes closes off unhandled-exception paths that previously turned a single bad input, a slow network call, or a race condition into a 500 error, a stuck UI, or a corrupted local file.

- **Crash-on-malformed-input eliminated across the API surface.** Eight routes in `settings_routes.py` (create/update document type, prompt version create/merge/update, retention policy update, both iVault sync routes — Tasks 39, 41, 44, 45) now validate JSON body shape and field types before use, replacing unhandled `AttributeError`/`ValueError`/`TypeError` 500s with clean 400 responses. The same pattern was applied to `document_routes.py`'s `PATCH /documents/<id>` (Task 36).
- **PDF/OCR/DOCX conversion pipeline is now crash-resistant end to end.** Every conversion entry point that previously let a corrupt or malformed file propagate an unhandled exception now catches it and degrades gracefully: highlighted-PDF export (Task 46), searchable-PDF export (Task 54), plain rasterization (Task 67), DOCX→PDF conversion (Task 53), and ReportLab-based structured export (Task 64) all now return a fallback document or a clean error instead of crashing the worker thread mid-request. OCR failures specifically are no longer disguised as real extracted text (Task 68) — a corrupted "OCR extraction failed" string can no longer be silently stored and shown to a user as if it were document content.
- **Resource leaks under error conditions closed.** `fitz` (PyMuPDF) document handles in the highlighted- and searchable-PDF services are now guaranteed to close via `try/finally` even when processing fails mid-page (Tasks 47, 54), preventing file-handle and native-memory leaks that would accumulate under sustained export failures.
- **Silent data-loss and false-success bugs fixed.** `document_routes.py`'s guided-conversation handlers no longer swallow failed DB commits and report success anyway — they now roll back and return an honest error (Task 30). A mid-batch upload failure now cleans up already-saved files and reports which upload failed instead of orphaning files with no job record (Task 34). `_snake_case`'s empty-string collision, which could silently drop a second iVault property sharing a field name, is fixed by hashing to a guaranteed-unique fallback (Task 39).
- **Concurrency races removed.** `learned_structures.json` reads/writes are now serialized with a lock and land atomically via temp-file-then-`os.replace` (Tasks 18, 27), eliminating both write interleaving and half-written-file reads under `qwen_service.py`'s per-upload background-thread model. `settings_routes.py`'s create/rename-document-type TOCTOU window is closed by catching `IntegrityError` and returning 409 instead of a raw 500 (Task 43). `retention_service.py`'s purge scheduler now uses a MySQL distributed lock so multi-worker (gunicorn) deployments can't run the daily purge redundantly or concurrently against the same rows (Task 56).
- **Long-running SSE/polling connections can no longer hang forever.** The upload-progress stream (Task 38), the iVault-recognition stream (Task 32), and the frontend's `EventSource.onerror` handler (Task 16) all now enforce a bounded timeout with an explicit error/reconnect path, instead of holding a worker thread or a broken UI state open indefinitely if a background job dies silently.
- **Frontend JS hardened against the same class of bug.** Unguarded `JSON.parse` in the SSE handler (Task 6), unguarded `.replace()` on a possibly-undefined `document_type` (Task 12), and DOM-scraping code that ran outside its own `try/catch` in `saveFields` (Task 13) are all now defensively guarded, so a single malformed payload degrades to a visible error message instead of silently breaking the page.
- **Schema/DB integrity hardened.** `document_model.py`'s `get_fields()`/`get_text_blocks()` now catch malformed JSON instead of raising on every document read (Task 50) — this path executes on essentially every document view, so it was the single highest-blast-radius unhandled-exception risk in the fix set. A composite unique constraint on `(document_type_id, field_name)` now prevents ambiguous duplicate field rows at the DB level (Task 52). Startup schema migrations in `app.py` now check `information_schema` before altering tables and log real failures instead of swallowing them with `except: pass` (Task 71) — previously a genuine DB connectivity/permissions failure at startup would be indistinguishable from the benign "column already exists" case.

**Net effect:** the fix set removes essentially every unhandled-exception path that was reachable from user-controlled input (bad JSON, corrupt files, malformed model output) or from time-dependent conditions (races, dead background threads), converting crashes into either a clean 4xx response, a fallback artifact, or a visible, honest error state.

## 2. Performance & Speed

- **Redundant DB round-trips eliminated in the hot document-processing path.** `qwen_service.py` now caches custom-field and active-doc-type-name lookups per document-processing call instead of re-querying per invocation, cutting 5+ redundant DB round-trips down to one per document (Task 21). The same N+1 pattern in `classify_single_page` — previously one identical DB query per page of a split PDF — is now a single query per split job (Task 24). `document_model.py`'s `to_dict()` methods no longer issue a per-row `PromptVersion.query.get()`; listing routes now batch-fetch and eager-load (`selectinload`/`joinedload`) before serializing (Task 51).
- **Third-party network calls no longer block the request path.** Both FX-rate lookup call sites in `document_routes.py`'s `/ask` chat handler (Tasks 28, 29) now route through a shared, cached helper with a 180-second TTL and a stale-cache fallback, instead of issuing a blocking `urllib` call with a 5-second timeout on every relevant chat message. This decouples `/ask`'s latency and availability from a third-party API's uptime.
- **Expensive OCR/OCR-adjacent work is now cached instead of recomputed per export.** Tesseract word-box extraction for highlighted PDF export (Task 49) and full `ocrmypdf` OCR passes for searchable PDF export (Task 55) are both now cached (in-memory and on-disk-by-content-hash respectively), cutting repeated-export latency from a full OCR pass down to a cache read.
- **Frontend rendering work scoped to what's actually visible.** `renderAllPages()` now only rasterizes visible pages (plus a small buffer) instead of every page in the document on every zoom/pan action, eliminating multi-second synchronous freezes on large multi-page PDFs (Task 11). PDF find-in-page search is now debounced (200ms) instead of rebuilding the full text index on every keystroke, removing input lag and layout thrashing (Task 7).
- **Unbounded resource growth capped.** In-memory job-tracking dicts in `document_routes.py` (upload jobs, Task 31; iVault jobs, Task 33) are now swept on a TTL instead of retaining every historical job's extracted data for the life of the process. The frontend's `qaThreads` cache is now capped at 15 entries with LRU eviction instead of retaining detached DOM fragments for every document ever opened in a session (Task 9). A stalled/looping local-model generation now aborts after ~45s of no progress instead of buffering unbounded output for up to the full 600s timeout (Task 19).
- **List endpoints and batch pipelines bounded.** `get_all_documents`/`get_by_type` now paginate (capped at 200) and exclude `raw_text` from list responses instead of serializing every matching row's full text in one payload (Task 35). Split-PDF pipelines now reject oversized PDFs via a configurable page cap and process/discard pages incrementally instead of holding every rendered page in memory at once (Task 26); plain PDF rasterization got the same page-count cap (Task 66). The daily retention purge now processes documents in bounded 200-row batches via keyset pagination instead of loading the entire unpurged table into memory (Task 58).

**Net effect:** the fix set removes the majority of unbounded-memory and redundant-I/O patterns in the extraction and export pipelines, and converts several synchronous, uncached, per-request-expensive operations (FX lookups, OCR passes, DB lookups) into cached or batched calls — the biggest wins are on repeated-export latency and on worst-case memory under large/multi-page documents.

## 3. Developer & Environment Impact

- **Production container no longer runs a development server.** The Docker `CMD` now launches `waitress-serve` (a production WSGI server) via `entrypoint.sh` instead of `flask run` (Werkzeug's single-threaded dev server), which was already listed as a dependency but never actually invoked (Task 60). This is a meaningful stability/throughput difference under any concurrent production load.
- **Deployment is now observable and reproducible.** A `HEALTHCHECK` block was added to both the `Dockerfile` and `docker-compose.yml`, hitting a lightweight `/health` endpoint on an interval — previously `restart: unless-stopped` had no signal to act on if the Flask process hung (Task 65). Every dependency in `requirements.txt` is now version-pinned (e.g. `flask==3.1.3`, `cryptography==50.0.0`, `torch==2.10.0+cpu`), closing off the risk of a routine rebuild silently pulling a breaking or CVE-affected release (Task 74).
- **Ollama/local-model bootstrap hardened.** `ollama-entrypoint.sh` now derives the pulled model name from `OLLAMA_MODEL` instead of a hardcoded value that could drift from the app's actual configuration (Task 69), and its readiness loop now has a bounded retry count plus an explicit exit-code check on the pull step, so a crashed/never-ready Ollama server fails fast with a diagnostic message instead of hanging the container indefinitely (Task 70).
- **Test suite is now trustworthy, if still thin.** `test_connection.py` and `test_qwen.py` now exit non-zero on failure instead of printing-and-swallowing, so a broken DB connection or unreachable LM Studio endpoint will actually fail CI instead of reporting a false pass (Task 72). `test_rag_tenant_isolation.py`'s fake `chromadb`/`sentence_transformers` module stubs are now scoped and torn down via `tearDownModule()` instead of leaking into later test modules in the same pytest session (Task 62). *(Note: the broader test-coverage gap — Task 61 — was found only partially addressed and remains open; see the flagged-items note in the task file.)*
- **Debugging and operational tooling improved.** Startup schema migrations now log real failures via `information_schema` checks instead of an opaque `except: pass` (Task 71, also listed under Stability), meaning a future "the app started but a column is missing" incident will actually be traceable in logs. `prompt_studio_service.py`'s prompt-testing flow now fails with a clear `ValueError` naming the missing sample file instead of a confusing low-level file-not-found error surfacing from deep inside `process_document()` (Task 63) — directly reduces time-to-diagnosis for anyone debugging prompt versioning.
- **Cross-version compatibility fixed in the RAG layer.** `rag_service.py`'s multi-condition Chroma filter now explicitly uses `{"$and": [...]}` instead of a flat merged dict, which some `chromadb` versions reject outright — this was previously masked by a broad `except` that silently returned `[]`, making a filter-syntax break indistinguishable from "no matches" (Task 73). Query failures are now logged distinctly from genuine zero-result queries.

**Net effect:** the deployment story goes from "runs, but on a dev server with no health signal and unpinned deps" to a reproducible, observable production configuration; the test suite gained real pass/fail signal (though coverage breadth is still a known, tracked gap).

## 4. User Experience

- **Destructive and impactful actions now confirm before acting.** Changing a document's type (which re-extracts and can overwrite hand-corrected field values) now warns the user first, but only when there's actually something to lose (Task 4). Deleting a taught field-type hint now requires confirmation, matching every other destructive flow in the app, instead of a bare click firing an irreversible DELETE (Task 5). `settings_routes.py` now blocks deletion of built-in document types (invoice, receipt, etc.), which previously broke extraction app-wide until a restart re-seeded them (Task 40).
- **Errors are now visible instead of silent.** A network failure refreshing iVault record types now shows an explicit "refresh failed" message instead of leaving stale text with no explanation (Task 15). A malformed SSE progress payload now shows a status message and keeps listening, instead of silently killing the queue UI mid-upload (Task 6). PDF zoom/highlight actions that fail to render now surface a status message instead of leaving the viewer silently blank or half-rendered (Task 8). Field-saving errors are now caught and reported instead of leaving the UI stuck in edit mode with no feedback (Task 13).
- **Bulk and background operations report accurate outcomes.** The "reset" bulk-delete action now fires all deletes concurrently and reports an accurate "Deleted X/Y, Failed: ..." count instead of aborting the entire batch (and reporting nothing useful) on the first failed delete (Task 1). Guided in-chat corrections in `/ask` now give an honest failure signal if a fix doesn't persist, instead of the UI believing a correction was saved when it silently wasn't (Task 30). A mid-batch upload failure now reports specifically what failed instead of a generic 500 with orphaned files (Task 34).
- **UI stops getting stuck or showing stale/wrong state.** The card-export dropdown now closes on outside click instead of staying open and overlapping other cards (Task 2). Switching documents quickly no longer risks an earlier `/blocks` response overwriting the currently-open document's bounding-box highlights (Task 10). A brief network blip during a multi-file upload no longer kills the whole progress feed — the UI now tolerates transient drops for up to 30 seconds and keeps listening (Task 16).
- **Accessibility improved for keyboard and screen-reader users.** Folder cards, iVault type rows, and recent-document rows — previously plain `<div>`s with only an `onclick` handler — now carry `role="button"`, `tabindex="0"`, and Enter/Space keydown support, making them reachable via keyboard and correctly announced by assistive tech (Task 3). *(Note: a related fix to the sidebar nav and upload drop-zone, Task 14, was found to still have a broken HTML tag and remains open — that portion of the accessibility work is not yet functional.)*
- **Interactive performance directly felt by the user.** Large multi-page PDFs no longer freeze the UI for multiple seconds on every zoom/pan click (Task 11), and typing in the PDF find box no longer lags on large documents (Task 7) — both are direct, perceptible responsiveness improvements during normal document review.

**Net effect:** the fixes close the gap between "the backend did something" and "the user can see and trust what happened" — confirmations before data-loss, honest error states instead of silence, accurate partial-failure reporting, and two concrete responsiveness fixes users will notice immediately when reviewing large documents.
